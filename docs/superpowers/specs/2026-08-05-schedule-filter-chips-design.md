# 일정 시점 필터 칩 — 설계

작성일: 2026-08-05

## 배경

기업(프로젝트) 수가 늘어나면 기업 × 업무 격자가 세로로 길어져 원하는 기업을 찾기 어렵다.
현재 화면에는 검색·필터가 없고, 탭 3개(진행 중 / 교육 완료 / 전체보기)와 교육 날짜 오름차순 정렬만 있다.

담당자가 실제로 좁혀 보고 싶은 축은 **교육 일정 시점**이다. "이번주에 뭐가 있지",
"다음주 준비할 게 뭐지", "일정이 아직 안 잡힌 건 뭐지"가 반복되는 질문이다.

## 범위

교육 상태·미배정 인력·미완료 업무 등 다른 필터 축은 이번 작업에 포함하지 않는다.
일정 시점 하나만 넣고, 나중에 축을 추가할 수 있는 구조만 남긴다.

## 동작 명세

### 칩 배치

탭 바와 같은 줄, 오른쪽에 pill 칩 5개를 놓는다.

```
[진행 중 12] [교육 완료 8] [전체보기 10]   [전체] [이번주 3] [다음주 2] [이번달 7] [일정미입력 2]
```

기존 `.owner-chip` 스타일(pill, 활성 시 테두리·배경 강조)을 재사용한다. 새 디자인 언어를 추가하지 않는다.

칩 순서는 시간·범위 크기순으로 `전체 → 이번주 → 다음주 → 이번달 → 일정미입력`.

### 선택 방식

단일 선택. `이번주`는 대개 `이번달`의 부분집합이므로 다중 선택은 의미가 없다.

- 칩을 누르면 그 칩만 활성화되고 목록이 좁혀진다.
- 활성 칩을 다시 누르면 `전체`로 돌아간다.
- 초기 상태는 `전체`.

### 판정 규칙

기업의 모든 회차 날짜(`company.sessions[].dates[]`)를 펼쳐서, **하나라도** 구간에 걸치면 표시한다.
5일짜리 교육의 뒷회차만 이번주인 경우에도 누락되지 않는다.

주 시작은 월요일, 판정은 로컬 시간대 기준 날짜 단위(시각 무시)로 한다.

| 칩 | 정의 | 예 (오늘 = 2026-08-05, 수) |
|---|---|---|
| 전체 | 필터 없음 | — |
| 이번주 | 오늘이 속한 주의 월요일 ~ 일요일 | 08-03 ~ 08-09 |
| 다음주 | 그 다음 주의 월요일 ~ 일요일 | 08-10 ~ 08-16 |
| 이번달 | 오늘이 속한 달의 1일 ~ 말일 | 08-01 ~ 08-31 |
| 일정미입력 | 유효한 날짜가 하나도 없음 (`sessions[].dates`가 전부 비고 `startAt`도 없음) | — |

`sessions[].dates`에 값이 없으면 정렬과 동일하게 `company.startAt`을 폴백으로 사용한다.

구간은 서로 겹칠 수 있다. `다음주`가 월 경계를 넘으면 `이번달`에 없는 기업이 `다음주`에 잡힌다
(예: 8/31이 월요일이면 다음주는 08-31 ~ 09-06이므로 9월 초 교육도 `다음주`에 포함).
"다음주"는 달 경계와 무관한 사용자 기준 표현이므로 이 동작이 의도된 것이다.
단일 선택이라 겹침으로 인한 중복 표시 문제는 발생하지 않는다.

### 칩 숫자

현재 보고 있는 탭의 대상 집합을 기준으로 센다. `교육 완료` 탭에서 "이번주 3"이면
그 탭에서 실제로 보일 행이 3개다. 탭을 전환하면 숫자를 다시 계산한다.

### 적용 범위

세 탭 모두에 적용한다. 테이블 뷰(`진행 중`, `교육 완료`)와 카드 뷰(`전체보기`)가 같은 필터를 공유한다.

### 상태 유지

탭을 전환해도 선택한 칩은 유지한다. 새로고침하면 `전체`로 초기화한다.
필터가 켜진 것을 잊은 채 "기업이 사라졌다"고 오해하는 상황을 막기 위해 저장하지 않는다.

### 결과 0건

기존 빈 상태 UI(`empty-row` / `card-grid-empty`)를 재사용하고 문구만 "조건에 맞는 교육이 없습니다"로 바꾼다.
필터가 `전체`일 때는 기존 문구("진행 중인 프로젝트가 없습니다" 등)를 그대로 쓴다.

## 구현 구조

수정 대상은 `index.html` 한 파일이다.

### 추가

- 탭 바 마크업(425~429행 근처)에 칩 5개
- 모듈 변수 `currentDateFilter`— `'all' | 'thisWeek' | 'nextWeek' | 'thisMonth' | 'noDate'`, 초기값 `'all'`
- `getCompanyDates(company)` — 회차 날짜를 펼쳐 유효한 날짜 배열 반환 (`startAt` 폴백 포함)
- `matchesDateFilter(company, filter)` — 순수 함수. 위 판정 규칙 하나만 담당
- `getVisibleCompanies(tab, filter)` — 탭 조건 + 날짜 필터 + 날짜 오름차순 정렬을 거친 목록 반환
- `setDateFilter(filter)` — 상태 갱신 후 재렌더

### 정리

`renderBody`(1012행)와 `renderCardView`(1221행)에 `getEarliestDate` 정렬 로직이 글자 그대로 복제되어 있다.
필터를 양쪽에 또 복붙하면 세 번째 복제가 된다. 목록을 뽑는 부분을 `getVisibleCompanies`
하나로 합쳐 두 뷰가 같은 함수를 쓰게 한다. 앞으로 필터 축을 추가할 때 한 곳만 고치면 된다.

`renderSummary`(1146행)의 탭별 집합 계산도 같은 함수를 사용한다.

### 경계

- Supabase 데이터 구조, `state.json` 스키마, `server.js`, 스킬 20개는 수정하지 않는다.
- 순수 화면단 필터이므로 저장되는 데이터가 없다.

## 검증

수동 확인 항목:

1. 칩 미선택(`전체`) 상태에서 기존과 동일한 목록·정렬이 나온다
2. 회차가 여러 개인 기업에서 뒷회차만 이번주일 때 `이번주`에 잡힌다
3. 날짜가 전혀 없는 기업이 `일정미입력`에만 잡힌다
4. 칩 숫자와 필터 적용 후 실제 행 수가 일치한다 (세 탭 각각)
5. 탭 전환 시 칩 선택이 유지되고 숫자가 재계산된다
6. 새로고침하면 `전체`로 돌아간다
7. 결과 0건일 때 "조건에 맞는 교육이 없습니다"가 나온다
8. 전체보기 카드 뷰에도 같은 필터가 걸린다
