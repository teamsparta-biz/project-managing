# roster-fill — 고객사 제출용 명단 엑셀 채우기 설계

작성일: 2026-08-05
상태: 설계 승인됨, 구현 계획 대기

## 배경

고객사는 교육 전 강사·기술튜터 명단을 자기 양식의 엑셀로 요구한다. 보안 반입 심사나
출입 등록에 쓰이므로 양식을 우리가 바꿀 수 없고, 받은 파일에 값을 채워 돌려줘야 한다.

2026년 7월 3주 동안 이 작업이 4개 고객사에 6번 발생했다.

| 파일 | 고객사 |
|---|---|
| 삼성전자로직텍.xlsx | 삼성전자로지텍 |
| 삼성전자로지텍_임원교육_강사튜터정보.xlsx | 삼성전자로지텍 |
| 베니트_교육담당자.xlsx | 코오롱베니트 |
| 코오롱생명과학.xlsx | 코오롱생명과학 |
| 생명과학_강사명단.xlsx | 코오롱생명과학 |
| 코오롱글로벌_교육담당자.xlsx | 코오롱글로벌 |

기존 `tutor-info-share`는 ax-hub를 조회해 화면에 표로 보여주는 데서 끝난다. 그 표를
고객사 양식으로 옮기는 작업이 매번 수작업으로 남아 있고, 옮기는 과정이 오기입이 나는 지점이다.

## 목표

받은 xlsx의 빈 칸 중 ax-hub로 채울 수 있는 것을 채워 사본으로 저장한다.
채우지 못한 칸과 기존 값이 ax-hub와 다른 칸을 보고한다.

## 목표가 아닌 것

- 노트북 모델명·시리얼넘버 자동 채움 — ax-hub에 없는 데이터다.
- 고객사측 담당자(임직원) 정보 채움 — ax-hub 대상이 아니다.
- 구글 시트 직접 수정.
- 메일 발송 — 기존 메일 스킬들이 담당한다.
- 원본 파일 수정 — 항상 사본을 만든다.

## 조사 결과

### 양식의 공통 구조와 변이

6개 파일 전부에 `구분`(강사/기술튜터), `성명`, `이메일`, `차량 정보`가 있다.
대부분 `기간`, `연락처`, `비고`가 함께 있다.

고객사 그룹별로 양식이 재사용된다.

- **코오롱 3사**(베니트·생명과학·글로벌): 헤더가 거의 동일
  `No. | 기간 | 구분 | 성명 | 연락처 | 이메일 | 차량 정보 | 비고`
  1행은 제목행(`코오롱글로벌 AX Boot Camp 담당자 명단`), 2행이 실제 헤더다.
  코오롱생명과학.xlsx만 `계열사`, `지역` 컬럼이 추가된다.
- **삼성전자**: 위 필드에 `노트북 모델명`, `시리얼넘버`, `기타 기기 모델명`, `시리얼넘버`가
  붙는 보안 반입 양식이다. `교육생 노트북` 시트가 별도로 있다.

### 채우면 안 되는 기존 데이터

코오롱 양식 상단에는 `상시` 구분의 고정 블록이 있다(김성호·송인권·최문수·리나).
이들은 코오롱측 임직원이고 ax-hub에 없으며 이미 값이 채워져 있다.

### 차량 정보는 ax-hub MCP로 읽을 수 없다

`instructors` 테이블에 `car_plate`·`car_model`·`car_color`가 실제로 존재한다
(pg_attribute 조회 결과 24개 컬럼 확인). 그러나 MCP readonly 롤이 컬럼 화이트리스트로
차단해 조회가 거부된다. `gender`, `birth_date`도 같이 가려져 있다(PII 정책).

```
SELECT name, phone, email FROM instructors   → 정상
SELECT car_plate FROM instructors            → permission denied for table instructors
```

`describe_table`의 설명 텍스트는 `car_model/car_color/car_plate (070)`을 언급하지만
반환하는 컬럼 목록에는 없다. 설명 텍스트가 실제 권한과 어긋나 있다.

**관련 발견**: `parking-check-inquiry/SKILL.md` 110행이 `car_plate`를 조회하도록
지시한다. 현재 권한으로는 그 단계에서 실패한다. 이 스킬의 별도 점검이 필요하다.

따라서 차량 정보는 **기존 명단 파일에서 이월**하고 부족분만 사용자에게 확인받는다.

## 입력

```
/roster-fill 기업명:코오롱글로벌 교육명:AX Boot Camp [파일:경로]
```

- `파일` 생략 시 `산출물/문서/`에서 기업명이 포함된 xlsx를 찾는다. 여러 개면 사용자에게 묻는다.
- `기업명`이 없으면 사용자에게 묻는다.

## 처리 흐름

```
[1] 인자 파싱 → course 조회
[2] 대상 xlsx 양식 해부 (헤더 탐지 · 컬럼 매핑 · 기존 행 파악 · 양식 유형 판별)
[3] ax-hub 조회 (전 회차 배정 + 연락처 + 이메일)
[4] 차량 정보 이월 + 부족분 확인
[5] 채움 계획 미리보기 → 사용자 검수
[6] 사본 저장 + 리포트
```

### 1단계: course 조회

기존 `tutor-info-share`·`lecture-share`·`parking-check-inquiry`와 동일한 SQL을 쓴다.

```sql
SELECT c.id AS course_id, c.title AS training_name, c.status AS course_status
FROM courses c
JOIN deals d ON c.deal_id = d.id
JOIN clients cl ON d.client_id = cl.id
WHERE cl.name = %s
ORDER BY c.lecture_start DESC NULLS LAST
LIMIT 5;
```

1건이면 그것을 쓴다. 여러 건이면 `교육명` 부분 일치로 좁히고, 그래도 여러 건이면 사용자에게 묻는다.
찾지 못하면 오류를 안내하고 종료한다.

### 2단계: 양식 해부

**헤더 행 탐지** — 1행부터 최대 10행까지 훑어, 아래 별칭에 2개 이상 매칭되는 첫 행을
헤더 행으로 본다. 1행 고정은 안 된다(코오롱은 1행이 제목행).

**컬럼 별칭 매핑**

| 내부 필드 | 헤더 별칭 |
|---|---|
| `role` | 구분, 역할 |
| `name` | 성명, 이름 |
| `phone` | 연락처, 전화번호, 휴대폰, 휴대전화 |
| `email` | 이메일, 메일, e-mail |
| `car` | 차량 정보, 차량번호, 차량, 차번호 |
| `date` | 기간, 일자, 날짜, 교육일자 |

매칭은 공백 제거 후 부분 일치로 한다(`차량 정보` / `차량정보` 모두 매칭).

**매핑되지 않은 컬럼은 쓰기 대상에서 완전히 제외한다.**
`No.`, `계열사`, `지역`, `비고`, `노트북 모델명`, `시리얼넘버`, `기타 기기 모델명`이 해당한다.

**대상 시트 선택** — 시트가 여러 개면 헤더 매칭 점수가 가장 높은 시트를 쓴다.
삼성전자 파일의 `교육생 노트북` 시트는 매칭되지 않으므로 자동으로 제외된다.
점수가 동점이거나 모두 0이면 사용자에게 묻는다.

**양식 유형 판별**

| 유형 | 판별 기준 | 배치 |
|---|---|---|
| 일자별 반복형 | 기존 데이터 행에서 같은 `name`이 2회 이상 등장 | 일자 × 인원으로 행 생성 |
| 회차 통합형 | 같은 `name`이 1회씩만 등장 | 인원당 1행, 중복 제거 |

기존 데이터 행이 비어 있어 판별할 수 없으면 `date` 컬럼 유무로 추정한다
(`date` 있으면 일자별 반복형). 그래도 애매하면 사용자에게 묻는다.

### 3단계: ax-hub 조회

전 회차를 대상으로 한다(날짜 필터 없음). 인원·역할·연락처·이메일을 한 번에 가져온다.

```sql
SELECT
  cs.date,
  i.name,
  CASE
    WHEN left(a.qualification_id::text, 8) IN
      ('a7a605e9','888ee72c','07ecdab5','e39eeef7','ecdd7d85','7db139f7','2647f764')
      THEN '강사'
    WHEN left(a.qualification_id::text, 8) IN
      ('30976fac','a0af4d4f','fc59bde4')
      THEN '기술튜터'
  END AS role,
  i.phone,
  COALESCE(i.notion_email, i.email) AS email
FROM course_sessions cs
JOIN course_rounds cr ON cs.round_id = cr.id
JOIN assignments a ON a.course_session_id = cs.id
JOIN instructors i ON a.instructor_id = i.id
WHERE cr.course_id = %s
ORDER BY cs.date, role, i.name;
```

- `role`이 NULL인 행(강사·튜터 어느 자격도 아닌 배정)은 제외하고, 몇 건 제외됐는지 보고한다.
- 이메일은 `notion_email` 우선, 없으면 `email`. 둘 다 없으면 빈 칸으로 두고 미채움에 올린다.
- 결과가 없으면 배정된 인원이 없다고 안내하고 종료한다.

### 4단계: 차량 정보

ax-hub로 조회할 수 없으므로 다음 순서로 채운다.

1. **대상 파일 내 이월** — 같은 파일에 그 사람의 차량 값이 이미 있으면 그대로 둔다.
2. **다른 명단 파일에서 이월** — `산출물/문서/`의 다른 xlsx에서 같은 이름의 차량 값을 찾는다.
   찾으면 출처 파일명과 함께 사용자에게 보여주고 확인받는다.
3. **미확인** — 위에서 못 찾으면 빈 칸으로 두고 미채움에 올린다.
   사용자가 값을 주면 채운다. 대중교통 이용자는 `대중교통 이용`으로 적는다.

동명이인은 이월하지 않고 사용자에게 묻는다.

### 5단계: 검수 게이트

저장 전에 채움 계획을 보여준다. 고객사로 나가는 서류라 되돌리기가 비싸므로 생략하지 않는다.

```
📋 코오롱글로벌 AX Boot Camp — 명단 채움 계획
대상: 코오롱글로벌_교육담당자.xlsx / 시트 '강사명단' / 회차 통합형
헤더 행: 2행  ·  매핑된 컬럼: 구분, 성명, 연락처, 이메일, 차량 정보
건드리지 않는 컬럼: No., 기간, 비고

채울 행 (N건)
| 행 | 구분 | 성명 | 연락처 | 이메일 | 차량 정보 |
...

보존 (M건) — 이미 값이 있어 덮지 않음
| 행 | 성명 | 사유 |
| 3  | 김성호 | ax-hub에 없는 인원 (고객사 담당자) |

불일치 (K건) — 파일 값과 ax-hub 값이 다름. 덮지 않음
| 행 | 성명 | 필드 | 파일 값 | ax-hub 값 |

미채움 (L건)
| 성명 | 필드 | 사유 |
| 홍길동 | 차량 정보 | 이월 출처 없음 |

진행하려면 '검수 완료'를 입력하세요.
```

`검수 완료` 입력 시에만 6단계로 간다.

### 6단계: 저장

- 사본 경로: 원본과 같은 폴더에 `{원본명}_채움_{YYYYMMDD}.xlsx`
- 원본은 수정하지 않는다.
- 저장 후 서식 유실 가능성을 경고한다: openpyxl은 셀 값과 대부분의 셀 서식을 유지하지만
  차트·이미지·일부 조건부서식은 유실될 수 있다. 원본이 남아 있으니 필요하면 수동 대조한다.

## 보존 규칙

`sync-ax-hub`의 "사용자 입력값은 어떤 경우에도 수정·초기화·삭제하지 않는다"를 계승한다.

1. 값이 있는 셀은 덮어쓰지 않는다. ax-hub와 다르면 불일치로 보고만 한다.
2. ax-hub에 없는 이름의 행은 건드리지 않는다.
3. 매핑되지 않은 컬럼은 건드리지 않는다.
4. 대상 시트가 아닌 시트는 건드리지 않는다.
5. 원본 파일은 수정하지 않는다.

## 구성

```
.claude/skills/roster-fill/
  SKILL.md          흐름·규칙·출력 형식
  fill_roster.py    xlsx 해부·채움·리포트 (openpyxl)
```

`labor-cost-sheet`가 확립한 구조를 따른다 — SKILL.md가 절차와 판단 기준을 담고,
결정적 계산과 파일 조작은 파이썬 스크립트가 한다.

`allowed-tools`: `Bash`, `Read`, `mcp__ax-hub__query_sql`

## 검증

기존 6개 파일로 회귀 검증한다. 각 파일에 대해 확인할 것:

1. 헤더 행을 올바르게 찾는가 (코오롱 2행, 삼성전자 1행).
2. 대상 시트를 올바르게 고르는가 (삼성전자 파일에서 `교육생 노트북`을 고르지 않는가).
3. 양식 유형을 올바르게 판별하는가 (삼성전자 일자별 반복형, 코오롱 회차 통합형).
4. 매핑되지 않은 컬럼의 값이 채움 전후로 완전히 동일한가.
5. 코오롱 양식의 `상시` 블록 4명이 그대로 남아 있는가.
6. 원본 파일의 수정 시각이 변하지 않았는가.

4·5·6은 파일을 다시 읽어 셀 단위로 비교해 확인한다.
