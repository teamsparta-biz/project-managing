# PDF/노션 → 가로 슬라이드 변환

## Overview
A4 세로 문서(교안·보고서 등)나 노션 페이지를 16:9 랜드스케이프 PPT 슬라이드 스타일 PDF로 재구성한다. 원본을 그대로 회전시키는 게 아니라,
**내용을 슬라이드 단위로 재설계한 HTML을 새로 만들고 Chrome headless로 PDF 인쇄**하는 방식. `template.html`에 재사용 가능한
슬라이드 컴포넌트(표지/표/상하 구성/좌우 비교)가 있다.

## When to use
- 세로 A4 PDF나 노션 페이지 링크를 "가로로", "PPT 장표처럼", "슬라이드 느낌으로" 바꿔달라는 요청
- 이미 있는 보고서·교안(PDF 또는 노션)을 발표/시각 자료용으로 재포맷할 때

**해당 안 함**: 원본 HTML/MD 소스가 있고 단순 서식 수정만 필요한 경우 → 그 소스를 직접 고치는 게 빠름(아래 1단계에서 먼저 확인).

## 워크플로우

### 1. 원본 파악
- **PDF인 경우**: Read 도구로 PDF 전체 내용을 읽는다.
  - **실제 페이지 수는 텍스트 확인이 아니라 구조로 검증한다** — 문서 안 "1/68" 같은 푸터 표기는 원본 발췌 흔적일 수 있어 신뢰할 수 없음:
    ```bash
    python3 -c "
    import re
    data = open('파일경로','rb').read()
    print(len(re.findall(rb'/Type\s*/Page[^s]', data)))
    "
    ```
- **노션 링크인 경우**: `notion-fetch`로 페이지 전체 내용을 가져온다. 페이지 안에 하위 페이지·인라인 DB가 있으면 각각 fetch해서 원본 구조(소제목 순서, 표, 하위 항목)를 그대로 파악한다. 이미지·첨부는 링크만 남기지 말고 내용 파악에 필요하면 별도로 확인.
- 같은 제목의 소스 MD/HTML이 프로젝트 안에 있는지 Grep으로 확인. 있으면 그걸 편집하는 게 우선.

### 2. 슬라이드 분해 설계
- A4 한 페이지 ≈ 슬라이드 1.5~2장 비율로 잡는다(밀도 높은 표/섹션은 쪼갠다).
- 원칙: **슬라이드 1장 = 개념/표 1묶음**. 소제목 단위로 자르고, 문단은 불릿으로 압축한다.
- 표지 슬라이드 1장 + 본문 슬라이드들 + (있으면) 요약/인용 마무리 슬라이드로 구성.
- **`template.html`의 기본 폰트 크기는 17px 이상이다** — 가독성을 위해 이보다 작게 낮추지 않는다. 폰트가 커진 만큼 한 슬라이드에 들어가는 표 행 수·불릿 개수는 이전보다 적게 잡아야 한다 — 표는 한 슬라이드에 6~7행을 넘기지 말고, 행이 더 많으면 슬라이드를 나눈다.

### 3. HTML 작성
- `template.html`을 복사해서 쓴다(원본은 읽기 전용, 수정 금지).
- `@page { size: 338mm 190mm; }` = 16:9 비율. 색상 테마(`--navy`, `--red` 등)는 문서 성격에 맞게 바꿔도 됨.
- `.slide` 하나 = 슬라이드 한 장. `.content` 안에 표/카드/불릿 컴포넌트를 조합하되, **기본은 위→아래로 쌓는 상하 구성**이다. `.two-col`(좌우 분할)은 서로 다른 두 항목을 나란히 비교시킬 때만 예외적으로 쓴다 — 하나의 프롬프트·설명을 억지로 반씩 잘라 좌우에 배치하지 않는다.
- 원본 텍스트·수치는 임의로 요약·각색하지 말고 그대로 옮긴다 — 압축은 "몇 문단을 불릿으로" 수준까지만.
- **원본이 교육·워크숍용 실습 자료라면, 각 실습 Step에 딸린 "입력할 프롬프트"(교육생이 그 자리에서 그대로 타이핑해 실행하는 문구)는 절대 요약·생략하지 않고 `.prompt` 컴포넌트로 원문 그대로 싣는다.** 개조식 압축 규칙은 설명 문장에 적용되는 것이고, 프롬프트 원문 자체는 개조식 대상이 아니다 — 교육생이 장표만 보고 실습을 따라갈 수 있어야 하므로, 프롬프트가 여러 개인 실습은 슬라이드를 나누어서라도 전부 싣는다. 하나의 슬라이드에 여러 프롬프트를 쌓을 때는 각 프롬프트 위에 `.mini-h`로 "Step N — 목적"을 짧게 붙인다. 여러 줄로 된 지침문·Skill 정의처럼 줄바꿈 구조가 있는 프롬프트는 `.prompt.pre`(공백·줄바꿈 그대로 보존)를 쓴다.
- **불릿(`ul.bullets`)·카드·표 셀 문장은 개조식으로 쓴다**: "~습니다/~합니다/~됩니다" 같은 서술형 종결어미를 쓰지 않고, 명사형(~함/~함/~완료)이나 명사구로 끝맺는다.
  - 나쁜 예: "이 프로세스는 데이터를 자동으로 수집하고 검증합니다." → 좋은 예: "데이터 자동 수집·검증"
  - 나쁜 예: "결과 보고서는 매주 금요일에 발송됩니다." → 좋은 예: "결과 보고서 매주 금요일 발송"
  - 원본이 이미 개조식이면 그대로 두고, 완결된 서술문일 때만 명사형으로 다듬는다.
  - **개조식 변환 금지 대상 — 아래는 서술형 그대로 둔다(잘라내지 않는다)**: 조건·단서("~인 경우에만", "단,", "예외적으로"), 인과·전제("~하므로", "~함에 따라"), 수치·기간·금액·고유명사, 법적/계약 문구, 자격·책임 소재를 규정하는 문장. 이런 요소를 명사형으로 뭉치면 조건 관계가 사라질 수 있으므로, 축약이 애매하면 서술형을 유지하고 폰트/줄바꿈으로 슬라이드에 맞춘다.
  - 표지 슬라이드의 `.desc`(소개 문단), `.quote`(인용) 등 문단형으로 의도된 컴포넌트는 예외 — 자연스러운 문장체 유지.
- **`.content`는 기본적으로 세로 중앙 정렬(flex column + justify-content:center)이고, `.two-col` 안의 `.col`도 각자 세로 중앙 정렬된다** — 내용이 적은 슬라이드가 위쪽에만 붙어 아래쪽에 여백이 몰리는 것과, 2단 레이아웃에서 한쪽 칼럼이 짧아 그쪽만 위로 뜨는 정렬 어긋남을 자동으로 막아 준다. 표지처럼 맨 위부터 채워야 하는 특수 슬라이드만 `class="content top"`으로 상단 정렬을 쓴다.
- **"프롬프트 + 예상 결과/잘 안될 때" 패턴은 `.two-col`로 좌우 반씩 쪼개지 말고, 프롬프트를 전체 폭으로 먼저 두고 그 아래에 결과·주의사항을 배치한다.** `.prompt`를 컬럼 절반 폭에 가두면 줄바꿈이 잦아져 읽기 나쁘고, 남는 옆 칸과 억지로 맞추다 정렬이 어긋난다. 표준 마크업:
  ```html
  <h1 class="slide-title sm"><span class="step-num">N</span>제목</h1>
  <div class="rule sm"></div>
  <p style="...">목적 — 한 줄 설명</p>
  <div class="prompt">전체 폭 프롬프트</div>
  <div class="grid2">
    <div class="result-box"><div class="lbl">예상 결과</div><p>...</p></div>
    <div class="fix-box"><div class="lbl">잘 안될 때</div><p>...</p></div>
  </div>
  ```
  결과·주의사항이 하나뿐이면 `.grid2`로 감싸지 말고 그 박스 하나만 전체 폭으로 둔다. 한 슬라이드에 서로 다른 두 Step을 나란히 비교시키는 의도적 2단 구성(예: Step A와 Step B를 좌우로 대비)은 이 규칙의 예외 — 그 경우도 각 Step 내부의 프롬프트는 자기 칼럼 폭 전체를 쓰게 하고, 결과·주의 박스는 두 Step 몫을 모아 칼럼 아래 `.grid2`로 뺀다.

### 4. PDF 변환 (Chrome headless)
```bash
CHROME="/c/Program Files/Google/Chrome/Application/chrome.exe"
HTML='G:\...\문서명_slides.html'   # Windows 경로(역슬래시) 필수 — git-bash /g/... 경로는 인식 안 됨
PDF='G:\...\문서명.pdf'
"$CHROME" --headless --disable-gpu --no-pdf-header-footer --print-to-pdf="$PDF" "$HTML"
```
- 변환 후 반드시 재확인:
  ```bash
  python3 -c "
  import re
  data = open('PDF경로','rb').read()
  print(len(re.findall(rb'/Type\s*/Page[^s]', data)))
  print(re.search(rb'/MediaBox\s*\[([^\]]+)\]', data).group(1))
  "
  ```
  MediaBox의 가로>세로(16:9에 가까운 비율)인지 확인.

### 5. 레이아웃 검수
표/카드가 많은 슬라이드는 넘침·겹침이 잘 생기므로 스크린샷으로 직접 확인한다. 96dpi 기준 1mm ≈ 3.7795px이므로, N번째(0-indexed)
슬라이드를 보려면 `body{margin-top: -(N * 190 * 3.7795)px}` 오프셋을 임시 복사본에 넣고 캡처한다:
```bash
python3 - <<'EOF'
import subprocess
html_path = r"G:\...\문서명_slides.html"
tmp_path = r"C:\Temp\slidecheck.html"
mm_to_px = 96 / 25.4
slide_h_px = 190 * mm_to_px          # 슬라이드 높이(190mm) → px
with open(html_path, encoding="utf-8") as f:
    html = f.read()
for n in [0, 3, 7]:                   # 확인할 슬라이드 번호(0-indexed) 목록
    offset = -int(slide_h_px * n)
    out = html.replace("<style>", f"<style>body{{margin-top:{offset}px !important;}}")
    with open(tmp_path, "w", encoding="utf-8") as f:
        f.write(out)
    subprocess.run([
        r"C:\Program Files\Google\Chrome\Application\chrome.exe",
        "--headless", "--disable-gpu", "--hide-scrollbars",
        "--force-device-scale-factor=1.4", "--window-size=1278,718",
        f"--screenshot=C:\\Temp\\slide{n}.png", tmp_path,
    ])
EOF
```
표지(0번) · 표가 가장 많은/복잡한 슬라이드 · 텍스트 줄 수가 가장 많은 슬라이드 · 마지막 슬라이드는 반드시 확인 — 슬라이드를 다 쓴 뒤
내용량 기준으로 후보를 눈으로 골라 번호 목록에 넣는다. Read 도구로 PNG를 열어 넘침(텍스트 잘림)·겹침·빈 공간 과다를 검수.
검수 끝나면 임시 스크린샷/복사본(`C:\Temp\slide*.png`, `slidecheck.html`) 삭제.

### 6. 산출물 정리
- **원본 파일을 덮어쓰기 전 반드시 사용자에게 확인받는다** — 되돌릴 수 없는 작업이므로, 기본값으로 원본을 덮어쓰지 않는다. `문서명_slides.pdf`처럼 새 파일명으로 저장한 뒤, "원본을 이 파일로 덮어쓸까요, 별도 파일로 둘까요?"를 사용자에게 물어 답을 받고 나서 필요하면 덮어쓴다. 사용자가 처음부터 "원본 덮어써줘"라고 명시했다면 재확인 없이 바로 덮어써도 된다.
- 편집 가능한 HTML 원본(`문서명_slides.html`)은 같은 폴더에 남겨서, 이후 문구 수정 시 재사용할 수 있게 한다.
