# 인건비 시트 작성 스킬

강사·기술튜터가 구글폼으로 제출한 **로우데이터**를 「**인건비 정산 요청 시트**」 양식으로 변환합니다.

**지급액의 출처는 로우데이터입니다.** 시급을 곱해 새로 산정하지 않습니다 — 제출자가 적어낸 금액이
정산의 근거이고, ax-hub 계산은 오기입을 잡기 위한 **검산**으로만 씁니다.

조회·변환 전용입니다. **구글 시트를 자동으로 수정하지 않습니다.** 최종 붙여넣기는 사용자가 검수 후 직접 합니다.

---

## 전체 흐름

```
[1단계] 대상 월 결정 (인자 없으면 전월)
    ↓
[2단계] xlsx 최신 여부 확인 → 필요하면 사용자에게 재다운로드 요청
    ↓
[3단계] ax-hub SQL 1회 → 결과 rows 를 JSON 파일로 저장 (검산 입력)
    ↓
[4단계] build_rows.py 실행 → TSV + 확인필요 출력
    ↓
[5단계] 확인필요를 사람이 읽을 수 있게 정리해 함께 제시
    ↓
[6단계] 요청시트 포맷 xlsx 로 저장 → 완료
```

## 1단계: 대상 월 결정

인자에서 `월:YYYY-MM`을 추출합니다. 없으면 **전월**(정산은 월 마감 후에 하므로).
어느 달을 집계하는지 출력 첫 줄에 반드시 밝힙니다.

월 판정 기준은 로우데이터의 **교육시작일~교육종료일이 해당 월과 겹치는지**입니다.
6월~7월에 걸친 행은 포함하되 `월 경계 걸침`으로 경고에 올립니다.

## 3단계: ax-hub 검산 데이터 (SQL 1회)

`'송찬호'`와 날짜 두 곳만 바꿔 **한 번만** 실행합니다.

```sql
WITH me AS (
  SELECT email FROM profiles
  WHERE display_name = '송찬호' AND email LIKE '%teamsparta.co' LIMIT 1
), own AS (
  SELECT c.id, c.title, cl.name AS client
  FROM courses c
  JOIN deals d ON c.deal_id = d.id
  JOIN clients cl ON d.client_id = cl.id
  WHERE c.manager_email = (SELECT email FROM me)
)
SELECT i.name AS person, o.client, o.title, q.code AS qual,
       count(DISTINCT cs.date) AS days,
       min(cs.date)::text AS d1, max(cs.date)::text AS d2,
       sum(CASE WHEN cs.start_time IS NULL OR cs.end_time IS NULL THEN NULL
                WHEN cs.start_time <= 12 AND cs.end_time >= 13
                     THEN cs.end_time - cs.start_time - 1
                ELSE cs.end_time - cs.start_time END) AS hours
FROM own o
JOIN course_rounds cr ON cr.course_id = o.id
JOIN course_sessions cs ON cs.round_id = cr.id
JOIN assignments a ON a.course_session_id = cs.id
JOIN qualification_catalog q ON q.id = a.qualification_id
JOIN instructors i ON i.id = a.instructor_id
WHERE cs.date >= DATE '2026-07-01' AND cs.date < DATE '2026-08-01'
GROUP BY i.name, o.client, o.title, q.code
ORDER BY i.name, min(cs.date);
```

결과의 `rows` 배열을 **그대로** 스크래치패드에 `axhub.json`으로 저장합니다.
시급 곱셈은 스크립트가 `rates.json`을 읽어서 합니다 — 직접 계산하지 마세요.

**사람×등급이 아니라 사람×교육 단위로 뽑습니다.** 합계만 맞춰보면 "한 사람이 −780,000"까지만 보이고,
그게 시간 오차인지 교육 1건 통째 누락인지 구분되지 않습니다. 교육 건별로 있어야 4단계의 검증이 됩니다.
`d1`·`d2`에 `::text`를 붙여야 JSON에 문자열로 떨어집니다.

**설계 주의점**

- 담당 교육 판정은 `courses.manager_email` 기준(`/sync-ax-hub`와 동일). 0행이면 이름 불일치를 먼저 의심합니다.
- `status` 필터를 걸지 않습니다. 지난달 교육은 이미 `closed`·`tax_invoice`인 경우가 많지만 정산 대상입니다.
- 그룹 키에 `qual`이 들어갑니다. 한 사람이 같은 달에 주강사·기술튜터로 섞여 배정될 수 있고, 합치면 단가가 섞입니다.
  `qual` 접두어가 역할입니다 — `main_*`=주강사, `tutor_*`=기술튜터, `mentor_*`=멘토, `special_*`=특강.
  스크립트가 `역할` 열로 풀어서 보여주므로 SQL에서 따로 뽑지 않습니다.
- 시간은 `end_time - start_time`, **점심시간(12~13시)이 교육 시간에 포함되면 1시간 공제**합니다.
  9~15시는 6시간이 아니라 **5시간**입니다. 총 시간이 몇 시간인지가 아니라 12~13시를 물고 있는지가 기준입니다.
- 검산을 건너뛰려면 `--axhub`를 빼고 실행합니다. 그때는 금액불일치·미제출이 나오지 않습니다.

## 4단계: 변환 실행

```bash
cd ".claude/skills/labor-cost-sheet"
python build_rows.py --month 2026-07 --pm 송찬호 --axhub "<스크래치패드>/axhub.json"
```

스크립트가 출력하는 것:

| 섹션 | 내용 |
|---|---|
| 머리말 | 대상 월·담당 PM·행 수·xlsx 수정일·합계 |
| `### TSV` | 요청시트 A~U열 값. 헤더 없이 데이터 행만 |
| `### 수식행용` | 로우데이터 행번호 → P(고객사명) / O(기수) |
| `### 확인필요` | 미매칭·오기입·금액불일치·미제출 |

**출력을 사람이 손으로 고치지 마세요.** 매핑 규칙이 틀렸다면 `build_rows.py`를 고칩니다.

### 컬럼 매핑 (요청시트 수식과 동일하게 맞춰져 있음)

| 열 | 값 | 출처 |
|---|---|---|
| A 타임스탬프 | 제출 시각 원문 | 로우데이터 A |
| B 지급 여부 | 빈칸 | 재무팀이 체크 |
| C 작성자(담당 PM) | 담당 PM | 로우데이터 H |
| D 이름(식별자) | 실명으로 조회 | 「인건비 정보」 B→C |
| E 실명 | 성함 | 로우데이터 B |
| F·G 체크 칸 | 빈칸 | — |
| H·I 근무시작/종료일 | `YYYY-MM-DD` | 로우데이터 C·D |
| J 팀 / K 프로덕트 | `AX교육팀` / `B2B` | 고정 |
| L 근무유형 | 기술튜터→`튜터-관리,실시간`, 주강사→`튜터-강의사용/제작료` | 로우데이터 E |
| M 트랙명 / N 식별코드 | 표준 고객사명으로 조회 | 「식별코드」 D→C·B |
| O 기수 | 빈칸 | 수동 |
| P 고객사명 | **표준 고객사명으로 정규화** | 「식별코드」 D |
| Q 내용 | `[원문 고객사]교육명` | 로우데이터 F·G |
| R 총 지급액(세전) | 숫자만 | 로우데이터 I |
| S 한글표기 | 500만원 이상일 때만 (`칠백이십만원`) | R에서 변환 |
| T 참고/메모 | **ax-hub 기준 시급 × 시간** (`ax-hub 기준 30,000원/h × 24h`) | rates.json × ax-hub 시간 |
| U 강사/기술튜터 | 원문 그대로 | 로우데이터 E |

**P열이 이 스킬의 핵심입니다.** 로우데이터의 고객사 표기(`SK 하이닉스`, `코오롱 생명과학`)는
「식별코드」 시트의 표준명(`SK하이닉스`)과 자주 어긋나고, P가 어긋나면 M·N 수식이 빈칸이 됩니다.
스크립트는 공백·괄호·기호를 지운 키로 매칭하고, **실패하면 원문을 그대로 두고 경고**합니다.
유사 후보를 보여주지만 **자동으로 갖다 붙이지 않습니다** — `코오롱베니트`를 `코오롱`으로 바꾸면
엉뚱한 프로젝트에 비용이 붙습니다. 표준명 확정은 사용자 몫입니다.

빈 칸도 **탭은 유지**해야 붙여넣기 시 열이 밀리지 않습니다.

### T열 시급·시간 (2026-08-04 추가)

로우데이터에는 시급·시간 칸이 없습니다. 그래서 `--axhub`를 줄 때 T(참고/메모)에 **ax-hub 기준
시급 × 시간**을 적습니다. 시급은 `rates.json`, 시간은 ax-hub 세션 시간(점심 공제)입니다.

- **지급액 산정 근거가 아니라 참고 수치입니다.** R열(총 지급액)은 여전히 로우데이터 제출값이고,
  T열 값을 곱해서 R을 다시 계산하지 않습니다. 그래서 문구 앞에 `ax-hub 기준`을 붙입니다.
- 시급이 다른 배정이 한 행에 걸치면 `100,000원/h × 14h + 30,000원/h × 8h`처럼 나열합니다.
- **같은 사람의 다른 교육과 날짜가 겹치면 시간이 합산돼 실제보다 커 보입니다.**
  (예: 김성진 그래디언트 07-16~30 안에 뉴트리원 07-18이 들어가 양쪽 다 27h)
  이런 행에는 `(다른 교육 N건과 기간 겹침 — 합산치)`를 붙입니다. 이 표시가 있는 행은
  `ax-hub 배정` 탭에서 원본을 보고 판단하세요.
- ax-hub 배정을 못 찾은 행은 T를 비웁니다(성함 오기입 등).
- 넣지 않으려면 `--no-rate-memo`를 붙입니다.

## 5단계: 출력 정리

TSV는 코드블록으로 그대로 내보내고, 그 아래에 요약을 붙입니다.

```
📋 2026-07 인건비 — 담당 PM 송찬호

- 32행 / 합계 23,379,997원
- 로우데이터 스냅샷: 2026-08-02

⚠️ 확인 필요
- 고객사 미매칭 N건 — P·M·N 직접 확인
- 금액불일치 N명 — 로우데이터와 ax-hub 계산 차이
- 미제출 N명 — 배정은 있으나 폼 제출 없음
- O(기수)·T(메모) 칸은 항상 비어 있음
```

- **금액불일치는 오류 단정이 아닙니다.** 교통비·숙박료를 별도 행으로 낸 경우, 등급이 다르게 배정된 경우
  모두 정상적으로 차이가 납니다. 차액과 함께 보여주고 판단은 사용자에게 맡깁니다.
- **미제출은 명수와 이름만** 전하고, 독촉 메시지를 자동으로 만들지 않습니다.
- 행이 많아도 임의로 자르지 않습니다. 60행을 넘으면 행 수를 먼저 알리고 전부 출력합니다.

## 6단계: xlsx 저장

TSV만으로는 다시 열어볼 수 없으므로, 같은 결과를 요청시트 포맷 xlsx로도 남깁니다.

```bash
cd ".claude/skills/labor-cost-sheet"
python export_xlsx.py --month 2026-07 --pm 송찬호 \
  --axhub "<스크래치패드>/axhub.json" \
  --out "산출물/인건비/2026-07_인건비_정산요청.xlsx"
```

- 저장 위치는 `산출물/인건비/{월}_인건비_정산요청.xlsx` 로 고정합니다.
- 헤더 문구·열 순서는 원본 워크북의 「인건비 정산 요청 시트」 1행을 **읽어서 그대로** 씁니다.
  헤더를 이 문서에 적어두지 마세요 (시트가 바뀌면 어긋납니다).
- **수식은 넣지 않습니다** — 원본의 수식은 같은 워크북의 로우데이터를 행 번호로 참조해서, 옮기면 깨집니다.

### 탭 구성

| 탭 | 내용 |
|---|---|
| `인건비 정산 요청 시트` | 붙여넣을 값. **이 탭만 원본 시트로 옮깁니다** |
| `ax-hub 배정` | ax-hub 배정 원본(사람·**역할**·고객사·교육명·등급·일수·기간·시간) + 적용 시급·계산액 |
| `검증` | 로우데이터 ↔ ax-hub 를 교육 건별로 대조한 결과. `역할(제출)`·`역할(ax-hub)` 두 열로 병기 |
| `확인필요` | 미매칭·오기입 등 사람 단위 경고 |

**ax-hub 값은 절대 요청시트 탭에 섞지 않습니다.** 정산 근거는 로우데이터 제출값이고, ax-hub 계산액은
근거를 대조하기 위한 참고 수치입니다. 한 탭에 섞이면 어느 쪽을 붙여넣어야 하는지 알 수 없게 됩니다.

`검증` 탭의 판정은 **로우데이터 행과 ax-hub 배정을 사람 + 기간 겹침으로 묶어** 냅니다. 고객사·교육명
표기가 양쪽에서 다르므로(`신라면세` vs `신라면세점`, `코오롱베니트` vs `코오롱생명과학 교육`)
이름으로는 이을 수 없습니다.

| 판정 | 뜻 | 색 |
|---|---|---|
| `제출<계산` | 과소 제출 의심 — 우선 확인 | 주황 |
| `미제출` | ax-hub 배정만 있고 제출 행 없음 | 주황 |
| `제출>계산` | 경비·초과근무일 수 있음 | 노랑 |
| `배정없음` | 제출은 있으나 ax-hub 배정 없음 | 노랑 |
| `단가미정` | rates.json에 시급 없음 — 대조 불가 | 회색 |
| `일치` | 금액 동일 | 연두 |

**역할 대조.** 로우데이터 E열(강사/기술튜터)과 ax-hub `qual` 접두어를 나란히 놓고, 두 값이 겹치지
않으면 `역할(제출)`·`역할(ax-hub)` 칸을 주황으로 칠하고 `확인필요`에 `역할 불일치`로 올립니다.
역할이 어긋나면 단가가 3만원/시간과 10만원/시간만큼 벌어지므로 금액 차이보다 먼저 봐야 합니다.
한 사람이 같은 달에 두 역할로 배정될 수 있으니(주강사·기술튜터 병행) 겹치는 값이 하나라도 있으면
불일치로 보지 않습니다.

**한계:** 같은 사람의 서로 다른 교육이 날짜 구간으로 겹치면 한 덩어리로 묶입니다
(예: 충청에너지 07-20~27 안에 코오롱베니트 07-21이 들어감). 합계 차액은 맞지만 교육 건별로는
쪼개지지 않으니, 묶인 행은 `ax-hub 배정` 탭에서 원본을 보고 판단합니다.
- 근무시작/종료일은 진짜 날짜, 총 지급액은 숫자로 씁니다. 문자열로 넣으면 시트에서 정렬·합계가 안 됩니다.
- 이 파일에도 실명·금액이 들어갑니다. `.gitignore`의 `*.xlsx`에 걸리는지 확인하고 커밋하지 않습니다.

## 부록: ax-hub 배정만으로 표 만들기

로우데이터 없이 **배정 기준**으로만 인건비 규모를 보고 싶을 때 씁니다.
로우데이터를 안 읽으니 미제출·금액불일치 판정도 없습니다.

```bash
cd ".claude/skills/labor-cost-sheet"
python axhub_only.py --axhub "<스크래치패드>/axhub.json" \
  --out "산출물/인건비/2026-07_ax-hub_인건비.xlsx"
```

열은 이렇습니다.

| 열 | 값 |
|---|---|
| 성명 / 근무시작일 / 근무종료일 | 배정 기준. 그 사람이 그 교육에 배정된 첫날~마지막날 |
| 고객사명 | `clients.name` 원문 (「식별코드」 표준명이 아님) |
| 교육명 | `[고객사명] 교육명` |
| **시급** | `rates.json`의 등급별 시급 (연노랑 배경 — 수정 대상) |
| **교육시간(점심 공제)** | ax-hub 세션 시간 합 (연노랑 배경 — 수정 대상) |
| 강의료 | **`=시급 × 교육시간` 수식** — 산정치 |
| 교통비 / 숙박비 / 세팅 | **빈칸** (연노랑 배경). 영수증·증빙을 보고 사람이 채웁니다 |
| 여비 합계 | `=SUM(교통비:세팅)` |
| 총 지급액 | `=강의료 + 여비 합계` |
| 강사/기술튜터 | `qual` 접두어에서 푼 역할 |

**시급·교육시간은 이 표에서 직접 고치는 칸입니다** (2026-08-04 확정). 연노랑으로 칠해 두었고,
값을 바꾸면 강의료·총 지급액이 수식으로 따라옵니다. rates.json 시급은 실제 계약 단가와 어긋날 수
있으니(권한 차단으로 원장 조회 불가) 계약서를 보고 이 칸을 고치는 것이 정상 경로입니다.
시급이 `null`인 등급은 칸을 비우고 **회색**으로 칠합니다 — 0원이 아니라 미정이라는 뜻입니다.
맨 아래 합계 행에는 교육시간 합계도 들어가고, 시급은 합계가 의미 없어 비웁니다.

강의료·여비·총 지급액은 수식이라 **Excel이나 구글 시트에서 열어야 값이 보입니다.**
드라이브 빠른 미리보기는 재계산을 하지 않아 빈칸으로 보일 수 있습니다.

교육명 앞에 이미 같은 고객사가 대괄호로 붙어 있으면(`[삼성증권] AI 실무 교육 과정`) 겹쳐 붙이지 않습니다.
여비·총 지급액은 **수식**이라 교통비·숙박비·세팅을 입력하면 바로 반영됩니다. 맨 아래 한 줄 띄고 합계 행이 있고,
필터를 걸면 딸려 올라가지 않게 자동필터 범위 밖에 둡니다.

**여비 금액을 추정해서 채우지 마세요.** ax-hub에도 로우데이터 폼에도 교통비·숙박비 필드가 없습니다
(`engagements`는 권한 차단, 폼은 A~I열까지). 로우데이터 제출액과 산정 강의료의 차액이 여비인 경우가
많지만 등급 오배정·초과근무로도 차이가 나므로, 차액을 여비 칸에 옮겨 적지 않습니다.

**강의료도 산정치입니다.** 실제 계약 단가와 어긋날 수 있고 정산 근거는 로우데이터 제출값입니다.
이 파일을 요청시트에 그대로 붙여넣지 마세요.

## 주의사항

- **지급액을 다시 계산하지 마세요.** 로우데이터 I열이 정산 근거입니다. `rates.json`은 검산 전용입니다.
- 로우데이터에 제출 행이 없으면 정산 행도 없습니다. 배정만으로 행을 만들지 않습니다.
- 인건비 원장(`engagements`)과 `qualification_catalog.master_hourly_rate`는 ax-hub에서 권한 차단(마이그 192)이라
  `rates.json`이 유일한 시급 출처이고 실제 계약 단가와 어긋날 수 있습니다. 검산 결과는 참고치입니다.
- 「인건비 정보」 탭의 전화번호·주민등록번호는 **읽지도 출력하지도 않습니다.** 스크립트는 B·C열만 씁니다.
  같은 이유로 xlsx는 `.gitignore`의 `*.xlsx`에 걸려 있습니다 — 커밋하거나 예외 처리하지 마세요.
- 구글 시트를 직접 수정하지 않습니다. 출력은 붙여넣기 재료일 뿐입니다.
- 추측으로 칸을 채우지 않습니다. 모르는 값은 비우고 "확인 필요"에 올립니다.
