# 교육 경비(교통비·숙박비·추가비용) 정산 스킬

사용자가 `/edu-expense-settlement`를 실행하면, 지정한 교육에 배정된 **모든 강사·기술튜터**가 실제로 며칠·어느 날짜에 참여했는지 ax-hub DB에서 조회하고, 그 일정을 바탕으로 **교통비·숙박비·추가 비용**을 인원별로 정리해 표로 출력합니다.

핵심 규칙: **회차 사이에 공백일이 없이 연속되는 교육(예: 9/1-2 → 9/3-4)은 하나의 출장으로 보고 교통비를 1회만 지급**합니다. 회차 사이에 하루 이상 공백이 있으면(예: 9/4 → 9/8) 별도 출장으로 계산합니다.

---

## 전체 흐름 요약

```
[1단계] 인자에서 기업명/교육명 파싱 → ax-hub에서 course 조회
    ↓
[2단계] 해당 course의 전체 회차·일자별 배정(강사·기술튜터) 조회
    ↓
[3단계] 인원별 참여일을 연속 구간(출장 단위)으로 그룹핑
    ↓
[4단계] 교통비/숙박비 단가 확인 (인자에 없으면 사용자에게 질문). 추가 비용은 먼저 묻지 않고 사용자가 언급한 경우만 반영
    ↓
[5단계] 인원별 표 출력 (참여일 · 출장 구간 · 교통비 · 숙박비 · 추가비용 · 합계)
    ↓
[6단계] Slack DM 공유 요청 시 전송
```

---

## 1단계: 인자 파싱 및 course 조회

명령 인자에서 `기업명:`, `교육명:`, `교통비:`, `숙박비:`를 추출합니다.

```sql
SELECT c.id AS course_id, c.title AS training_name, c.status AS course_status
FROM courses c
JOIN deals d ON c.deal_id = d.id
JOIN clients cl ON d.client_id = cl.id
WHERE cl.name = '기업명'
ORDER BY c.lecture_start DESC NULLS LAST
LIMIT 5;
```

- 결과가 1건이면 해당 `course_id` 사용.
- 여러 건이면 `교육명`(부분 일치)으로 좁히고, 그래도 여러 건이면 사용자에게 확인합니다.
- `기업명`이 없으면 사용자에게 기업명(및 필요 시 교육명)을 질문합니다.
- course를 찾지 못하면 오류를 안내하고 종료합니다.

---

## 2단계: 전체 회차·일자별 배정 조회

1단계의 `course_id`로 **모든 회차(과거 포함, 날짜 제한 없음)**의 강사·기술튜터 배정을 조회합니다. 지난 교육의 경비도 정산 대상이 될 수 있으므로 `tutor-info-share`와 달리 오늘 이후로 필터링하지 않습니다.

```sql
SELECT cs.date, i.id AS instructor_id, i.name, qc.category, qc.display_name
FROM assignments a
JOIN course_sessions cs ON cs.id = a.course_session_id
JOIN course_rounds cr ON cr.id = cs.round_id
JOIN instructors i ON i.id = a.instructor_id
JOIN qualification_catalog qc ON qc.id = a.qualification_id
WHERE cr.course_id = 'course_id'
ORDER BY i.name, cs.date;
```

- 결과가 없으면 "배정된 인원이 없습니다"라고 안내하고 종료합니다.

---

## 3단계: 참여일을 출장(연속 구간) 단위로 그룹핑

인원(`instructor_id`)별로 날짜를 오름차순 정렬한 뒤, **하루 차이(연속된 날짜)**로 이어지는 구간을 하나의 출장으로 묶습니다.

- 날짜 간격이 1일이면 같은 출장 구간에 포함.
- 날짜 간격이 2일 이상이면 새로운 출장 구간 시작.
- 예: `9/1,9/2,9/3,9/4,9/8,9/9` → `[9/1~9/4]`, `[9/8~9/9]` = 출장 2회.

이 그룹핑 결과가 교통비 지급 횟수의 기준이 됩니다. 숙박비는 각 출장 구간의 박수(구간 일수 − 1, 최소 0)를 계산해 둡니다.

---

## 4단계: 단가 확인

- `교통비` 단가가 인자에 없으면 사용자에게 "출장 1회당 교통비 단가가 얼마인가요?"라고 질문합니다.
- 숙박이 필요한 교육인지 사용자에게 확인합니다. 필요하다면 `숙박비` 단가(1박당)를 질문합니다. 숙박이 불필요하면(당일 왕복 가능한 교육) 숙박비는 0으로 두고 표에서 생략합니다.
- **추가 비용**(식비, 자재비, 기타 실비 등)은 ax-hub에 저장되어 있지 않으므로 자동 조회하지 않고, 사용자에게 먼저 묻지도 않습니다. 사용자가 먼저 특정 인원의 추가 비용을 언급하면 그 금액만 반영하고, 언급이 없으면 전원 0으로 둡니다.

---

## 5단계: 결과 출력

```
📋 {기업명} {교육명} — 경비 정산

| 이름 | 역할 | 참여일 | 출장 구간 | 교통비(횟수) | 숙박비(박수) | 추가비용 | 합계 |
|---|---|---|---|---|---|---|---|
(인원별 1행. 출장 구간은 "9/1~9/4, 9/8~9/9"처럼 쉼표 구분.
 교통비 칸은 "50,000원 × 2회 = 100,000원" 형식.
 숙박이 없는 교육이면 숙박비 열 자체를 생략.
 추가비용이 전원 0이면 그 인원 칸은 "-"로 표시.)

총 교통비: N회 × 단가 = 금액
총 숙박비: N박 × 단가 = 금액 (숙박 있는 경우만)
총 추가비용: 금액 (있는 경우만)
**총 경비: 합계**
```

## 6단계: Slack DM 공유 (요청 시)

사용자가 "슬랙으로 공유해줘", "DM으로 보내줘"처럼 요청하면 5단계 표를 markdown 표 그대로 `mcp__plugin_slack_slack__slack_send_message`로 전송합니다. 수신 대상을 지정하지 않으면 로그인한 사용자 본인에게 DM으로 보냅니다(채널 ID로 본인 user_id 사용). 특정 채널이나 다른 사람을 지정하면 그 대상으로 보냅니다.

## 주의사항

- `mcp__ax-hub__query_sql`은 SELECT만 허용됩니다 (read-only).
- 교통비는 **일수가 아니라 연속 출장 구간 수** 기준으로 계산합니다 — 회차가 이어져 있으면 중간 회차 경계와 무관하게 1회만 지급.
- 추가 비용은 DB에 없는 정보이므로 절대 임의로 추정하지 않고, 사용자가 알려준 값만 반영합니다. 추가 비용 유무를 사용자에게 먼저 질문하지 않습니다.
- 단가(교통비·숙박비)를 사용자가 알려주지 않으면 임의 기본값을 쓰지 않고 반드시 질문합니다.
