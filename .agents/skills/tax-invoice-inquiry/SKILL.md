# 세금계산서 발행 확인 메일 초안 생성 스킬

사용자가 `/tax-invoice-inquiry`를 실행하면, **교육 완료 후 고객사 담당자에게 세금계산서 발행 진행 가능 여부를 확인하는 메일** 초안을 작성합니다.
사용자가 '검수 완료'라고 입력하면 Gmail 임시보관함에 저장합니다.

---

## 전체 흐름 요약

```
[1단계]   정보 수집 (한 번에)
    ↓
[1-1단계] 만족도 점수 자동 조회 (ax-hub 우선, 없으면 구글시트)
    ↓
[2단계]   메일 초안 출력
    → 사용자 확인 및 수정 요청 반영
    ↓
[2-1단계] 만족도 PDF 생성 + (승인 시) 드라이브 링크 공유 (점수가 있을 때만)
    ↓
[3단계]   사용자가 "검수 완료"라고 입력하면 Gmail 임시보관함에 저장
    → 완료
```

---

## 0단계: 발신자 이름 자동 조회

1. `G:\내 드라이브\Project_managing_tool\.env` 파일을 Read 도구로 읽어 `USER_EMAIL` 값을 파싱합니다.
2. `USER_EMAIL`이 있으면 아래 SQL로 ax-hub에서 display_name을 조회합니다:

```sql
SELECT display_name FROM profiles
WHERE email = 'USER_EMAIL'
LIMIT 1;
```

3. 조회된 `display_name`을 `{발신자이름}`으로 사용합니다.
4. `USER_EMAIL`이 없거나 조회 결과가 없으면 사용자에게 이름을 질문합니다.

---

## 1단계: 정보 수집

인자로 제공되지 않은 항목은 **한 번에 모아서** 질문합니다 (항목별로 나눠 묻지 않음).

수집할 정보:

| 항목 | 필수 여부 | 설명 | 예시 |
|------|----------|------|------|
| 기업명 | 선택 | 고객사(계열사) 이름 — 웹앱 버튼 클릭 시 자동 전달, 별도로 묻지 않음 | 삼성바이오로직스 |
| 교육명 | 선택 | 교육 과정명 — 웹앱 버튼 클릭 시 자동 전달, 별도로 묻지 않음 | AI 교육과정 패키지 |
| 수신자 이름 | 필수 | 고객사 담당자 이름 | 김지혜 |
| 수신자 직함 | 필수 | 담당자 직함 | 팀장 |
| 만족도 점수 | 자동 조회 | 교육 만족도조사 점수 — 사용자에게 묻지 않고 1-1단계에서 자동 조회 | 4.6 |
| 수신자 이메일 | 권장 | Gmail 임시저장 수신자 주소 | contact@samsung.com |

> 기업명·교육명은 필수 질문 항목이 아닙니다. 인자로 전달되지 않아도 추가로 묻지 않으며, 메일 본문에는 직접 노출하지 않습니다(맥락 파악용). 단, 만족도 점수 자동 조회에는 필요하므로 둘 다 없으면 이 단계는 건너뜁니다.
> 발신자 이름은 0단계에서 ax-hub에서 자동 조회한 값을 사용합니다. 다를 경우 사용자가 언급할 것.
> **입력되지 않은 항목은 추가로 묻지 않고 해당 항목 자체를 메일에서 생략합니다.**
> 수신자 이메일을 처음에 받지 못한 경우, '검수 완료' 직전에 요청합니다.

---

## 1-1단계: 만족도 점수 자동 조회 (ax-hub 우선)

기업명·교육명이 모두 있으면 다음 순서로 만족도 점수를 조회합니다. 사용자에게 점수를 직접 묻지 않습니다.

1. **ax-hub `survey_sync_*` 조회** (우선 소스, [[feedback_satisfaction_source_axhub]]):
   ```sql
   -- ① courses에서 course.id 확인
   SELECT c.id FROM courses c
   JOIN deals d ON c.deal_id = d.id
   JOIN clients cl ON d.client_id = cl.id
   WHERE cl.name = '{기업명}' AND c.title = '{교육명}';

   -- ② survey_sync_courses.axhub_course_id로 survey_sync 쪽 course_id 조회
   -- ③ survey_sync_surveys에서 해당 course_id의 survey_id(들) 조회
   -- ④ survey_sync_questions에서 만족도 6문항(마지막 6개, "교육 후 나는~" 자기평가 문항 제외)의 question_id 조회
   -- ⑤ survey_sync_answers JOIN survey_sync_responses로 6문항 value_text::numeric 평균 + 응답 인원(n) 계산
   ```
   문항별 평균과 응답 인원(n)도 함께 계산해 둡니다(2단계 PDF 첨부에 사용).
2. **응답이 0건이면**: ax-hub에 아직 동기화되지 않은 것이므로, 구글 드라이브에서 `title contains '{기업명}' and title contains '만족도'` 로 응답 시트를 찾아 `ax-satisfaction-check` 방식(6개 만족도 문항 평균)으로 대체 계산합니다.
3. **둘 다 없으면(응답 0건 + 시트도 없음)**: 만족도 문장·첨부를 생략하고, 사용자에게 점수를 알고 있으면 알려달라고 안내합니다.
4. 사용자가 점수를 직접 정정해 주면 그 값을 그대로 사용합니다(재계산하지 않음).

---

## 2단계: 메일 초안 출력

1단계에서 수집한 정보를 바탕으로 메일 초안을 작성합니다.

**목적**: 교육 완료 후 세금계산서 발행 진행 가능 여부 확인

**제목**: `[팀스파르타] 세금계산서 발행 관련 문의드립니다`

**형식**:
```
{수신자이름} {수신자직함}님, 안녕하세요.
팀스파르타 {발신자이름}입니다.

교육과 관련하여 세심하게 챙겨주신 덕분에 교육을 잘 마무리할 수 있었습니다.
[만족도 점수 있을 경우]
교육 전반에 대한 만족도 조사 결과는 {만족도점수}점으로 확인되었습니다.
관련 로우 데이터를 첨부하오니 확인 부탁드립니다.

추가로 세금계산서 발행을 진행해도 될지 회신 부탁드리겠습니다.

감사합니다.
{발신자이름} 드림
```

**조건별 처리**:
- 만족도 점수가 없으면 만족도 문장과 로우 데이터 첨부 안내 두 줄 모두 생략
- 만족도 점수가 있으면 두 줄 모두 포함
- "아울러" 표현은 사용하지 않습니다 ([[feedback_tax_invoice_wording]]).
- 사업자등록증 사본 요청 문구는 넣지 않습니다 — 팀스파르타가 이미 보유하고 있어 요청할 필요가 없습니다 ([[feedback_tax_invoice_no_biz_cert_request]]). 사용자가 특정 건에서 필요하다고 언급하면 그때만 추가합니다.

메일 초안 출력 후 반드시 아래 문구로 마무리합니다:

> **수정할 내용이 있으면 말씀해 주세요. 내용이 확인되셨으면 "검수 완료"라고 입력해 주시면 Gmail 임시보관함에 저장합니다.**

사용자가 수정을 요청하면 반영 후 다시 출력하고 같은 문구로 대기합니다.

---

## 2-1단계: 만족도 로우 데이터 PDF 생성 (만족도 점수가 있을 때만)

> **PDF를 base64로 인코딩해 `create_draft`에 직접 첨부하지 않습니다.** 2026-09-07 실측: 3만자대 base64 문자열도 읽는 데만 3만 토큰 이상 소모되어 통째로 다시 출력해야 하는 첨부 호출까지 감안하면 비현실적입니다 ([[project_satisfaction_pdf_attachment]] 갱신 내역 참고). 대신 아래처럼 구글 드라이브 링크 방식을 씁니다.

1-1단계에서 만족도 점수를 구했다면, "검수 완료" 처리 시 공유할 PDF를 미리 준비합니다.

1. `data/.satisfaction_pdf_{기업명}.json`에 아래 형식으로 Write:
   ```json
   {
     "company": "{기업명}",
     "course": "{교육명}",
     "respondentCount": 46,
     "overallAvg": 4.6,
     "questions": [
       { "label": "전체 교육 과정에 대한 전반적인 만족도", "avg": 4.7 },
       { "label": "콘텐츠의 깊이와 난이도", "avg": 4.5 },
       { "label": "강사 전문성·소통", "avg": 4.8 },
       { "label": "부가 자료 도움 정도", "avg": 4.4 },
       { "label": "튜터 멘토링 적극성", "avg": 4.6 },
       { "label": "회사 동료 추천 의향", "avg": 4.7 }
     ]
   }
   ```
   (1-1단계 ②에서 구글시트로 대체 계산한 경우도 동일한 형식으로 채웁니다. 문항별 평균을 못 구했으면 `questions`는 빈 배열로 둡니다.)
2. 실행:
   ```bash
   node scripts/satisfaction-pdf.js "data/.satisfaction_pdf_{기업명}.json" "data/.satisfaction_pdf_{기업명}.pdf"
   ```
   이 프로젝트 폴더는 사용자 구글 드라이브 동기화 폴더 안에 있어, 저장된 PDF는 곧 실제 구글 드라이브에도 나타납니다(`.b64.txt`는 더 이상 생성하지 않아도 됨 — 필요 없으면 무시).
3. `search_files`(`title contains '.satisfaction_pdf_{기업명}.pdf'`)로 동기화된 파일을 찾아 fileId를 확보합니다.
4. **사용자에게 반드시 확인**: 이 PDF를 외부 수신자(고객사 담당자) 이메일로 `share_file`(role: reader) 공유해도 될지 물어봅니다 — 외부 공유는 자동 승인되지 않는 민감한 동작입니다. 승인 시에만 공유하고 `viewUrl`을 메일 본문에 링크로 넣습니다. 거절하거나 확인 없이 진행해야 하면 PDF 언급 문장(로우 데이터 첨부 안내) 자체를 메일에서 빼고 본문만으로 진행합니다.
5. 파일 저장 실패나 Playwright 미설치 오류가 나면 PDF 준비를 생략하고 사용자에게 알립니다 — 메일 본문 자체는 정상 진행합니다.
6. 테스트/임시로 만든 `data/.satisfaction_pdf_*` 파일은 용무가 끝나면 삭제합니다(로컬 삭제 시 드라이브에서도 정리됨).

## 3단계: Gmail 임시보관함 저장

사용자가 "검수 완료"를 입력하면:

1. 수신자 이메일이 없는 경우 이 시점에 요청합니다.
2. 2-1단계에서 사용자가 외부 공유를 승인했다면, 메일 본문의 "관련 로우 데이터를 첨부하오니 확인 부탁드립니다." 문장을 "관련 로우 데이터 링크를 아래에 공유드립니다: {viewUrl}"처럼 링크 형태로 바꿉니다. 승인하지 않았다면 해당 문장 자체를 뺍니다.
3. Gmail `create_draft` 도구로 임시보관함에 저장합니다(`attachments` 필드는 사용하지 않음).
4. 저장 완료 후 아래 메시지를 출력합니다:

> **✅ 메일 초안이 Gmail 임시보관함에 저장되었습니다. 추가 수정이 필요하면 말씀해 주세요.**

Gmail 저장 실패 시 오류 내용을 안내하고 재시도 여부를 묻습니다.

---

## Gmail 임시저장 규칙

- 저장은 사용자가 "검수 완료"를 입력한 시점에만 실행합니다. 출력 직후 자동 저장하지 않습니다.
- 수신자 이메일 주소는 1단계에서 수집하며, 미수집 시 "검수 완료" 직전에 요청합니다.
- 저장 후 반드시 "Gmail 임시보관함에 저장되었습니다." 메시지를 출력합니다.
- Gmail 저장 실패 시 오류 내용을 안내하고 재시도 여부를 묻습니다.

## 주의사항

- 메일 초안은 사용자 확인 전까지 Gmail에 저장하지 않습니다 — 출력과 동시에 자동 저장 금지
- 수정 요청 시 해당 메일만 재출력하고, 확인 문구로 다시 대기
- **입력되지 않은 항목은 추가로 묻지 않고 해당 항목 전체를 메일에서 생략** (빈 칸이나 "(미정)" 등으로 채우지 않음)
- 만족도 PDF 첨부용 임시 파일(`data/.satisfaction_pdf_*`)만 예외적으로 저장하며, 그 외 산출물 파일 저장은 하지 않음
