# 패들렛 저장소 회차별 일정 작성 스킬

노션 교안 페이지에는 보통 `:패들렛: 패들렛 저장소`라는 토글이 있고, 그 안에 "N회차(M/D):" 형식으로 회차별 줄이 들어갑니다(실습 결과물을 회차별로 정리해 붙여넣기 위한 자리). 이 스킬은 **ax-hub에서 회차별 날짜를 조회해 그 줄들을 자동으로 채워 넣는 것**까지만 담당합니다. 실제 실습 결과물 링크를 각 줄에 채우는 것은 튜터/매니저가 수업 후 직접 합니다.

> **트리거**: "패들렛 저장소에 회차별 일정 적어줘", "패들렛 저장소 토글 채워줘" 등 요청 시, 또는 `/padlet-storage-schedule` 명령 입력 시.

---

## 전체 흐름

```
[1] 기업명/교육명 또는 노션 URL 확인 (인자 또는 질문)
    ↓
[2] ax-hub에서 course 조회 (기업명/교육명으로) — 노션 URL이 이미 있으면 건너뛰고 3으로
    ↓
[3] ax-hub에서 회차별 날짜 조회 (course_sessions → 날짜 오름차순으로 회차 번호 부여)
    ↓
[4] 노션 교안 페이지 확보 (workbooks.full_url 또는 notion-search)
    ↓
[5] 페이지에서 "패들렛 저장소" 토글 찾기 → 기존 내용 파악
    ↓
[6] 새 회차별 일정 텍스트 미리보기 → 사용자 검수
    ↓
[7] "검수완료" 입력 → notion-update-page로 토글 내용 교체
    ↓
[8] 결과 안내
```

---

## 1단계: 인자 확인

명령 인자에서 `기업명`(또는 첫 위치 인자)과 `교육명:`을 추출합니다. 노션 페이지 URL이 인자로 주어지면 2단계를 건너뛰고 바로 4단계(페이지 확보)로 갑니다. 둘 다 없으면 사용자에게 물어봅니다.

---

## 2단계: ax-hub course 조회

```sql
SELECT c.id AS course_id, c.title AS training_name
FROM courses c
JOIN deals d ON c.deal_id = d.id
JOIN clients cl ON d.client_id = cl.id
WHERE cl.name ILIKE '%{기업명}%'
ORDER BY c.lecture_start DESC NULLS LAST
LIMIT 5;
```

- 결과가 1건이면 그 `course_id` 사용.
- 여러 건이면 `교육명`(부분 일치)으로 좁히고, 그래도 여러 건이면 사용자에게 확인받습니다.
- 못 찾으면 노션 페이지 URL을 직접 물어봅니다 (ax-hub 조회 없이 4단계부터 진행 가능하지만, 그 경우 3단계 회차별 날짜는 사용자에게 직접 물어봐야 합니다).

---

## 3단계: 회차별 날짜 조회

```sql
SELECT DISTINCT cs.date
FROM course_sessions cs
JOIN course_rounds cr ON cs.round_id = cr.id
WHERE cr.course_id = '{course_id}'
ORDER BY cs.date;
```

- **날짜 1개 = 회차 1개**입니다 (칸반보드와 동일하게 일자별 보기 — [[project_per_date_sessions]] 참고). 날짜 오름차순으로 1회차, 2회차, ...를 순서대로 부여합니다.
- 날짜는 `M/D` 형식으로 표기합니다 (예: `2026-08-25` → `8/25`). 연도가 다른 회차가 섞여 있으면(드묾) `YY/M/D`로 표기해 구분합니다.
- 세션이 하나도 없으면 사용자에게 알리고 중단합니다.

---

## 4단계: 노션 교안 페이지 확보

이미 노션 URL을 인자로 받았으면 그대로 사용합니다. 그렇지 않으면:

```sql
SELECT w.full_url, w.shorten_url
FROM workbooks w
WHERE w.course_id = '{course_id}'
LIMIT 1;
```

- `full_url`이 노션 페이지 URL(`notion.so` 또는 `app.notion.com`)이면 그것을 사용합니다.
- 없거나 노션 URL이 아니면 `mcp__claude_ai_Notion__notion-search`로 교육명을 검색해 교안 페이지를 찾습니다 (보통 "교안 카드" 데이터소스 안의 페이지, 제목 형식 `[기업명] 교육명`).
- 검색 결과가 0건이면 사용자에게 정확한 URL을 물어봅니다. 여러 건이면 후보 제목·URL을 보여주고 확인받습니다.

---

## 5단계: "패들렛 저장소" 토글 찾기

`mcp__claude_ai_Notion__notion-fetch`로 페이지 본문을 가져옵니다. 본문에서 아래와 같은 형태의 토글 블록을 찾습니다 (아이콘/이모지 표기는 페이지마다 다를 수 있으니 `summary`에 "패들렛"과 "저장소"가 모두 포함되는지로 매칭):

```
<details>
<summary>:패들렛:패들렛 저장소</summary>
	1회차(8/25): 
</details>
```

- 토글을 찾지 못하면, 본문 전체에서 "패들렛"이 포함된 다른 토글/섹션이 있는지 확인해 후보를 보여주고 사용자에게 확인받습니다. 그래도 없으면 어디에 추가할지 물어봅니다 (임의로 새 토글을 만들지 않습니다).
- 토글 안에 이미 회차별 줄이 일부 채워져 있으면(예: 실습 결과물 링크가 이미 붙어있는 줄), **그 내용은 보존**합니다 — 콜론(`:`) 뒤에 이미 텍스트/링크가 있는 줄은 건드리지 않고, 비어 있는 줄만 새로 채우거나 회차 목록 자체를 3단계 조회 결과로 맞춥니다.
- 토글 안 회차 줄 개수가 3단계에서 조회한 회차 수와 다르면(예: 노션에는 3줄만 있는데 ax-hub엔 6회차) 차이를 사용자에게 알리고, 없는 회차 줄을 추가할지 확인받습니다.

---

## 6단계: 미리보기 및 검수

```
{교육명} 패들렛 저장소 — 회차별 일정 ({N}회차)

1회차(8/25): 
2회차(9/1): 
3회차(9/2): 
...

기존에 채워져 있던 내용: {있으면 나열, 없으면 "없음"}

노션 페이지: {URL}

확인되셨으면 "검수완료"라고 입력해 주세요.
```

> **중요**: 사용자가 "검수완료"를 입력하기 전까지 노션 페이지를 수정하지 않습니다. 수정 요청이 있으면 반영 후 다시 미리보기를 보여줍니다.

---

## 7단계: 노션 페이지 업데이트

`mcp__claude_ai_Notion__notion-update-page`를 `command: "update_content"`로 호출해 기존 토글 블록 전체(`old_str`)를 새 회차별 줄이 포함된 토글(`new_str`)로 교체합니다. 예:

```
old_str:
<details>
<summary>:패들렛:패들렛 저장소</summary>
	1회차(8/25): 
</details>

new_str:
<details>
<summary>:패들렛:패들렛 저장소</summary>
	1회차(8/25): 
	2회차(9/1): 
	3회차(9/2): 
	4회차(9/8): 
	5회차(9/9): 
	6회차(9/10): 
</details>
```

- 이미 채워진 줄(콜론 뒤 텍스트/링크가 있는 줄)은 `new_str`에서도 그 내용을 그대로 유지합니다.
- `old_str`은 `notion-fetch` 결과에서 실제로 복사해와 정확히 일치시킵니다 (토글 내부 공백·이모지 표기가 페이지마다 다를 수 있음).

---

## 8단계: 결과 안내

```
✅ {교육명} 노션 페이지의 '패들렛 저장소' 토글에 회차별 일정을 반영했습니다.

1회차(8/25)
2회차(9/1)
3회차(9/2)
...

노션 페이지: {URL}
```

---

## 주의사항

- `mcp__ax-hub__query_sql`은 SELECT만 허용됩니다 (read-only).
- 칸반보드/ax-hub 세션은 **일자별 보기**입니다 — 회차 번호는 이 스킬이 날짜 오름차순으로 새로 부여하는 것이며, `course_rounds.round_number`(옛 회차 단위, 분반 등 포함 가능)를 그대로 쓰지 않습니다.
- 토글 안에 이미 채워진 내용(실습 결과물 링크 등)은 절대 지우지 않습니다 — 빈 줄만 채우거나 누락된 회차 줄만 추가합니다.
- "패들렛 저장소" 토글을 찾지 못하면 임의로 새 토글을 만들지 않고 사용자에게 확인받습니다.
- 사용자가 "검수완료"를 입력하기 전까지 노션 페이지를 수정하지 않습니다.
